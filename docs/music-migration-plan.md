## Сводка

**Проблема:** VK отключил публичное API, Kate Mobile больше не может докачивать новую музыку.
Доступен только локальный кеш (MP3-файлы с названиями вида `Артист_Название_цифры.mp3`).
Нужно решение на годы вперёд, без привязки к VK.

**Решение:**
1. Развернуть **Navidrome** (self-hosted музыкальный сервер, Subsonic API) на **Oracle Cloud
   Free Tier** (ARM VPS, нужен апгрейд до PAYG для защиты от удаления через 60 дней).
2. Взять исходники музыки: кеш Kate Mobile (полностью выгружен в Mail.ru облако — единый
   источник аудиофайлов) + Shazam-история + Яндекс Музыка (небольшая часть) + VK-плейлисты
   для восстановления структуры и поиска недостающего.
3. Нормализовать **кеш Kate Mobile** (единственный источник аудиофайлов): **распарсить имена
   файлов** (формат `Артист_Название_цифры` → ID3-теги), затем через **beets** (структура
   папок, обложки альбомов). Shazam и Яндекс.Музыка — только списки, без файлов; их
   нормализация произойдёт на Этапе 5 после докачки.
4. Восстановить плейлисты VK 1:1 (копипаст страниц VK → fuzzy-матчинг с коллекцией) →
   `.m3u` файлы, которые подхватит Navidrome.
5. **Автоматически докачать** недостающие треки через **slskd** (Soulseek-клиент на Mac) —
   одноразовая операция на Этапе 5. После этого загрузка новой музыки — через Syncthing/SFTP,
   Soulseek больше не нужен. **yt-dlp исключён** (корпоративный запрет).
6. Настроить клиенты на всех устройствах (Mac, Windows, Android) с офлайн-кешем и, по
   возможности, единым интерфейсом.
7. Настроить бэкап музыки/базы Navidrome в облако Mail.ru через **WebDAV** (rclone не
   работает с Mail.ru — проверено). Бэкап данных **и** базы Navidrome — отдельно.
8. Сделать добавление новой музыки возможным с любого устройства: **Syncthing** между
   ноутбуком и VPS для основного сценария, **SFTP** с телефона для редких случаев.

**Инструмент выполнения:** Claude Code на Mac — вся ручная работа (серверная настройка,
скрипты нормализации, парсинг метаданных) делается через агента, пользователь только
принимает решения на развилках.

**Статус:** план зафиксирован, этапы не начаты.

**Репозиторий:** [roman-redl/selfhost-music](https://github.com/roman-redl/selfhost-music) — конфиги, скрипты, docker-compose, документация.

### Компоненты

| Компонент | Роль | Коротко |
|---|---|---|
| **Oracle Cloud VPS (PAYG)** | Хостинг | Бесплатный сервер 4 CPU / 24 GB RAM. PAYG-апгрейд защищает от автоматического удаления через 60 дней |
| **Navidrome** | Музыкальный сервер | Self-hosted аналог Spotify/Apple Music. Раздаёт музыку по Subsonic API, лёгкий (Go), только музыка |
| **Caddy** | HTTPS-прокси | Автоматический SSL (Let's Encrypt), проксирует запросы к Navidrome. Без него сервер недоступен из интернета |
| **beets** | Нормализация | Организует музыку: правильные теги, структура папок `Артист/Альбом/`, обложки. Не для распознавания (имена уже есть), а для порядка |
| **Скрипт парсинга имён** | Извлечение тегов | Берёт имя файла `Артист_Название_цифры.mp3` и записывает ID3-теги в MP3. Свой скрипт, не beets |
| **slskd** | Докачка недостающего (разово) | Soulseek-клиент, запускается на Mac **только на Этапе 5**. Агент ищет треки через API, качает локально. После докачки не нужен — новая музыка добавляется через Syncthing/SFTP |
| **Syncthing** | Доставка файлов на VPS | P2P-синхронизация папки `MusicInbox` между ноутбуком (Mac/Win) и VPS. Бросил файл в папку → через минуту в Navidrome |
| **SFTP (Material Files)** | Загрузка с телефона | Для редких случаев. Material Files — бесплатный файловый менеджер на Android с поддержкой SFTP. Закинул напрямую в `/music-inbox/` |
| **watcher + inotify** | Автообработка | Следит за `/music-inbox/`, при появлении новых файлов запускает beets и триггерит пересканирование Navidrome |
| **WebDAV (davfs2)** | Бэкап в облако | Монтирует Mail.ru облако как папку на VPS. Cron раз в день синхронизирует `/music/` и `/data/`. rclone не работает с Mail.ru |
| **Supersonic** | Десктоп-клиент | Бесплатный, Mac + Windows, полный офлайн-кеш (выбрал плейлист → слушаешь без интернета) |
| **Ultrasonic** | Android-клиент | Бесплатный, Material Design, полный офлайн-кеш. Альтернатива — Symfonium (~400₽ разово, лучший UI) |
| **Audiobookshelf** | Аудиокниги (будущее) | Отдельный сервис для аудиокниг: позиция, скорость, sleep timer. Не смешивается с музыкой |

## Контекст и решения (зафиксировано)

| Вопрос | Решение | Причина |
|---|---|---|
| Исполнение | Claude Code на Mac | Пользователь хочет максимум автоматизации через агента, времени мало |
| Сервер приложение | **Navidrome** (не Jellyfin) | Заточен только под музыку, легче (Go, ~50-100MB RAM), больше Subsonic-клиентов под музыку. Jellyfin имеет смысл только если понадобится видео — не требуется |
| Хостинг | **Oracle Cloud Free Tier** (ARM VPS, ~4 CPU / 24GB RAM) | Бесплатно, мощности достаточно. **Важно:** нужен апгрейд до PAYG (бесплатно в пределах лимитов), иначе Oracle удалит ВМ через 60 дней (политика с октября 2025). Также возможны задержки при создании ARM-инстанса — использовать retry-скрипт |
| Архитектура | **Полноценный сервер с хранением музыки на VPS** | Сложно менеджить бессерверный/P2P-вариант; основная сложность — первичная загрузка, дальше кеш на клиентах решает вопрос доступности |
| Основной источник аудио | **Кеш Kate Mobile → полностью выгружен в Mail.ru облако** (единый источник, не два раздельных) | Вся музыка уже лежит в облаке Mail.ru |
| Облако-бэкап | **Mail.ru облако (почтовое, не VK Cloud) через WebDAV** | Уже используется, там же лежит кеш. rclone не работает с Mail.ru (проверено) |
| Доп. источники | Shazam история + Яндекс Музыка (немного) + VK (только для восстановления плейлистов и поиска недостающего) | VK не как источник аудио, а как эталон плейлистов |
| Способ найти недостающее из VK | Скопировать страницу VK (плейлисты) в буфер обмена → текстовый fuzzy-матчинг | Никаких PDF/OCR; просто копипаст имени+исполнителя, до 40 треков на плейлист |
| Нормализация метаданных | **Скрипт парсинга имён файлов** (формат `Артист_Название_цифры`) → ID3-теги → **beets** для организации папок и обложек | 95% файлов уже содержат артиста и название в имени. AcousticID/Chromaprint не нужен — избыточен и плохо работает на русской музыке |
| Обложки треков | beets плагины `fetchart` + `embedart` автоматически найдут и вставят обложки альбомов | В кеше VK обложек нет — beets добавит |
| Докачка недостающих треков | **slskd (Soulseek)** — Docker-контейнер на VPS, агент дёргает API с Mac. Качество: 320kbps MP3 / FLAC | yt-dlp запрещён корпоративно. Soulseek имеет огромное покрытие русской музыки, скачивание идёт напрямую на VPS, ничего не ставится на Mac |
| Navidrome и загрузка файлов | Navidrome **не умеет** принимать файлы через API/клиенты — внешний механизм: **Syncthing + watcher** для ноутбука, **SFTP** для телефона | Navidrome только читает папку `/music`. Syncthing между ноутбуком и VPS синхронизирует папку-инбокс. С телефона — SFTP (Material Files) для редких загрузок |
| Доступ к серверу | **Публичный HTTPS через Caddy + домен** (Tailscale не подходит) | Пользователь на корпоративном Mac, нельзя включать сторонние VPN |
| Десктоп-клиент (Mac + Windows) | **Supersonic** (бесплатный, кроссплатформенный, полный офлайн-кеш) | Feishin не подходит — кеш частичный, без системной предзагрузки плейлистов. Supersonic: явный выбор треков/плейлистов для офлайна |
| Офлайн-кеш в браузере | Невозможен — браузерная версия Navidrome только стриминг | Для офлайна нужен нативный клиент |
| Android-клиент | Кандидат: **Ultrasonic** (бесплатный) как база; Symfonium (разовая покупка ~400₽) как опция получше | Пользователь предпочитает бесплатное; разовая покупка допустима, подписки — нет |
| Явно отклонено | AIMP, Foobar2000 | Пользователь считает интерфейс устаревшим, нужен современный UI |
| Явно отклонено | Symfonium по подписке, регулярная подписка любого клиента | Готов на разовую покупку, не на подписку |
| Явно отклонено | yt-dlp для докачки треков | Запрещён корпоративной политикой |
| Явно отклонено | rclone для бэкапа в Mail.ru | Не работает с Mail.ru (проверено) |
| Аудиокниги (будущее) | **Audiobookshelf** — отдельный сервис на том же VPS (Этап 9, опционально) | Navidrome не подходит для аудиокниг (позиция, скорость, sleep timer). Audiobookshelf решает всё это с бесплатным Android-клиентом |

### Открытые развилки (решить в начале этапа 1 и 5)

**Развилка 1 — десктоп-клиент:**

| Вариант | Платформы | Цена | Кеш офлайн | UI | Статус разработки |
|---|---|---|---|---|---|
| **Supersonic** (рекомендация) | Win/Mac/Linux | Бесплатно | **Полный** — явный выбор треков/плейлистов для офлайна | Современный, Material-стиль | Активная |
| Feishin | Win/Mac/Linux | Бесплатно | Частичный — только кеш прослушанного, без предзагрузки | Очень современный, похож на Apple Music/Spotify | Активная |
| Sonixd | Win/Mac/Linux | Бесплатно | Стриминг, кеш ограничен | Средний | Заброшен (форкнут в Feishin) |
| Встроенный веб-плеер Navidrome | Везде (браузер) | Бесплатно | **Нет** (только стриминг) | Приличный, не выдающийся | Активная (часть Navidrome) |

**Развилка 2 — Android-клиент:**

| Вариант | Цена | Кеш офлайн | Плейлисты | UI |
|---|---|---|---|---|
| **Ultrasonic** (рекомендация, бесплатный вариант) | Бесплатно | Полный | Синхронизация с сервером | Material Design, современный |
| Symfonium | ~400₽ разово | Полный, самый продуманный | Синхронизация + локальные | Лучший на Android, но платный |
| DSub | Бесплатно | Полный | Синхронизация | Работает, но интерфейс старее |
| Substreamer | Бесплатно/донат | Полный | Синхронизация | Средний |

**Развилка 3 — способ бэкапа в Mail.ru облако:** РЕШЕНО → **WebDAV (davfs2)**. rclone не работает с Mail.ru (проверено). Нужно создать пароль приложения в настройках безопасности Mail.ru и смонтировать облако как папку на VPS.

**Развилка 4 — рекомендации (опционально, отложено):** Navidrome не умеет алгоритмические рекомендации как Spotify/VK. Но есть способы добавить:

| Вариант | Цена | Суть | Сложность |
|---|---|---|---|
| **Navidrome Smart Playlists** (база) | Бесплатно, встроено | Правила вроде «топ-100 за месяц», «не слушал год», «4+ звёзд». Настраиваются в веб-интерфейсе | Нулевая |
| **Last.fm + scrobbling** | Бесплатно | Navidrome скробблит прослушивания на Last.fm. Last.fm изучает вкус и даёт рекомендации на своём сайте. Минус: рекомендации не внутри плеера | Низкая |
| **Maloja** | Бесплатно, Docker | Self-hosted сервер скробблинга рядом с Navidrome. Хранит историю локально, генерирует «похожее», «ты слушал год назад», статистику. Рекомендации внутри веб-интерфейса Maloja | Средняя |
| **Symfonium Mix** (Android) | ~400₽ разово | Клиент Symfonium на Android умеет генерировать микс на основе трека/альбома. Работает локально, без сервера. Десктоп-аналога нет | Нулевая (если уже куплен) |

**Рекомендация:** начать со Smart Playlists (бесплатно, сразу). Если хочется большего — добавить Maloja как Docker-контейнер. Если Maloja не оправдает — Last.fm как fallback.

## Подробный план

### Этап 1 — Инфраструктура (сервер)

**Цель:** поднять рабочий Navidrome на Oracle Cloud Free Tier, доступный со всех устройств.

**Статус:** ✅ завершён (2026-08-06).

**Конфигурация сервера:**
- Oracle Cloud, Frankfurt, PAYG
- Ampere A1, 4 OCPU, 24 GB RAM, 200 GB диск
- Ubuntu 24.04 aarch64, Docker 29.7.2
- Домен: DuckDNS (`redl-music.duckdns.org`) + Caddy + Let's Encrypt
- SSH-ключ: `~/.ssh/id_ed25519_oracle`

**Пути на VPS:**
| Путь | Назначение |
|------|-----------|
| `/opt/selfhost-music/` | Корень репозитория |
| `/opt/selfhost-music/music/` | Музыка (readonly для Navidrome) |
| `/opt/selfhost-music/music-inbox/` | Входящие файлы для обработки |
| `/opt/selfhost-music/data/` | База Navidrome |
| `/opt/duckdns/duck.sh` | Cron для обновления DuckDNS |

**Отклонения от исходного плана:**
- `rate_limit` в Caddyfile убран — не работает без плагина в бесплатной версии
- Порты 80/443 открывались вручную в Security List подсети Oracle
- Интерфейс Oracle изменился — нет вкладки Resources, инстанс создаётся через Compute → Instances
- Navidrome-пользователь создан, доступ проверен

Шаги (как было сделано):
1. Зарегистрировать Oracle Cloud Free Tier аккаунт (нужна карта, пользователь делает сам).
2. **Сразу апгрейднуть до PAYG** (Billing → Upgrade). Без этого Oracle удалит ВМ через 60
   дней (политика октября 2025). В пределах Free Tier лимитов плата $0.
3. Создать ARM-инстанс (Ampere A1, 4 OCPU / 24GB RAM). **Важно:** почти наверняка будет
   ошибка `Out of host capacity`. Запустить retry-скрипт
   ([oci-always-free](https://github.com/dan-hollis/oci-always-free)) и ждать — может занять
   от нескольких часов до нескольких дней. Скрипт пробует каждые 60 секунд.
4. Настроить базовую безопасность: SSH-ключ, отключить пароль, ufw на порты 22 (SSH),
   443 (HTTPS), закрыть остальное.
5. Установить Docker + Docker Compose.
6. Развернуть Navidrome через docker-compose:
   ```yaml
   version: '3'
   services:
     navidrome:
       image: deluan/navidrome:latest
       restart: unless-stopped
       ports:
         - "4533:4533"
       volumes:
         - ./data:/data
         - ./music:/music:ro
       environment:
         ND_MUSICFOLDER: /music
         ND_DATAFOLDER: /data
         ND_SCANSCHEDULE: "1h"
         ND_ENABLETRANSCODING: "true"
         ND_LOGLEVEL: info
   ```
7. Настроить HTTPS и доступ извне:
   - Tailscale не подходит — на корпоративном Mac нельзя включать сторонние VPN.
   - **Caddy** как reverse proxy с автоматическим Let's Encrypt.
   - Нужен домен. Бесплатный вариант — DuckDNS (`*.duckdns.org`). Более надёжный —
     свой домен за ~200-300₽/год.
   - Caddy автоматически получает SSL-сертификат, настраивает HTTPS, проксирует
     запросы на Navidrome (порт 4533).
   - Добавить rate-limiting в Caddy для защиты от брутфорса:
     ```
     handle {
         rate_limit {remote_host} 10r/s
         reverse_proxy navidrome:4533
     }
     ```
   - Итог: `https://music.<твой-домен>.duckdns.org` доступен из любого браузера.
8. Проверить доступ к веб-интерфейсу Navidrome с Mac.
9. Создать пользователя/пароль в Navidrome для дальнейшего использования в клиентах.

**Результат этапа:** Navidrome работает на VPS, доступен с Mac по домену, готов принимать

### Этап 3 — Парсинг имён файлов и нормализация (beets)

**Цель:** превратить сырой кеш в единую библиотеку `Артист - Название` с правильными
тегами и структурой папок, готовую к раздаче через Navidrome.

**Статус:** ✅ завершён (2026-08-07).

**Стратегия:** 95% файлов уже содержат артиста и название в имени
(`Yello_Oh Yeah_494949805_456240039.mp3`). Поэтому НЕ используем AcousticID/Chromaprint —
вместо этого парсим имена файлов → пишем ID3-теги → beets только для организации.

#### Выполненные шаги

1. **Установлены инструменты:**
   ```bash
   brew install beets         # beets 2.13.1
   pip3 install mutagen       # mutagen 1.48.1
   ```

2. **Скрипт `scripts/parse_filenames.py`:**
   - Парсит имена `Артист_Название_<owner_id>_<track_id>.mp3`
   - Отрезает два последних числовых сегмента (owner_id + track_id)
   - Разделитель артист/название — первый `_` в оставшейся части
   - Пишет ID3-теги (artist, title) через mutagen
   - Результат: 1026/1030 распарсено автоматически, 4 вручную
   - 4 ручных: 3 файла с отрицательными ID, 1 со сложным именем

3. **Настроен beets** (`~/.config/beets/config.yaml`):
   ```yaml
   directory: MusicRaw/Library/          # в репозитории!
   library: MusicRaw/beets-library.db
   import:
     copy: no      # файлы уже в репо
     move: no
     write: yes
   paths:
     singleton: Singletons/$artist - $title
   plugins: fetchart embedart fromfilename
   ```

4. **Импорт в beets:**
   - Команда: `beet import -A -q -s MusicRaw/kate_mobile/`
   - Флаги: `-A` (без автопривязки к MusicBrainz), `-q` (без интерактива),
     `-s` (синглтон-режим — каждый трек отдельно)
   - Результат: 997 треков импортированы, 33 дубликата пропущены
   - 642 уникальных артиста

5. **Отклонения от плана:**
   - Библиотека размещена в `MusicRaw/Library/` (в репозитории), а не в `~/Music/Library/`
     (правило: всё в репозитории, не засорять Mac)
   - Импорт в один проход, а не в два — дубликаты обработаны автоматически
   - `lastgenre` плагин не подключён (требует MusicBrainz, а у нас синглтоны без альбомов)
   - **Обложки не добавлены** — `fetchart`/`embedart` работают на уровне альбомов,
     а у кеша нет альбомной структуры. Обложки будут добавлены позже отдельным скриптом
     или через beets после восстановления альбомной информации на Этапе 5.

#### Структура после Этапа 3

```
MusicRaw/
├── kate_mobile/              ← 1030 MP3 (оригиналы кеша с ID3-тегами)
├── Library/                  ← 997 MP3 (нормализованная библиотека)
│   └── Singletons/
│       └── Артист - Название.mp3
├── beets-library.db          ← база beets
└── ... (playlists, shazam, yandex, youtube)
```

**Результат этапа:** нормализованная библиотека с ID3-тегами и структурой
`Singletons/Артист - Название.mp3`, готовая к fuzzy-матчингу плейлистов (Этап 4).

### Этап 4 — Восстановление плейлистов

**Цель:** все плейлисты из всех источников должны появиться в Navidrome.

**Как Navidrome работает с плейлистами:**
- Navidrome читает папку, указанную в `ND_PLAYLISTSPATH` (по умолчанию — подпапка
  внутри `ND_DATAFOLDER`).
- Любой `.m3u` файл в этой папке автоматически становится плейлистом при следующем
  сканировании.
- `.m3u` может содержать либо абсолютные/относительные пути к аудиофайлам, либо
  пустые строки — тогда Navidrome сам матчит по тегам артист+название.

**Источники плейлистов:**

| Источник | Файлов | Тип .m3u |
|----------|--------|----------|
| VK-плейлисты | 41 `.txt` | 41 `.m3u` (по одному на плейлист) |
| Яндекс.Музыка | 1 `.txt` | 1 `.m3u` («Яндекс Музыка») |
| YouTube «Топ песенки» | 1 `.txt` | 1 `.m3u` («YouTube Топ») |
| Shazam | 1 `.txt` | 1 `.m3u` («Shazam») — после ручной чистки |

Шаги:
1. Из текстовых файлов плейлистов (собранных на этапе 2) извлечь списки
   «Артист — Название» для каждого плейлиста (простой построчный парсинг).
2. Написать скрипт сопоставления (fuzzy-matching, `rapidfuzz` в Python) списка
   плейлиста с нормализованной библиотекой — находит наиболее вероятное
   соответствие по названию+исполнителю.
3. Для каждого совпадения с высокой уверенностью — добавить путь к файлу в `.m3u`.
4. Для несовпадений — пометить как «не найдено» → это недостающие треки (Этап 5).
5. **Общий список недостающего** собирается со всех источников, дедублицируется
   и передаётся на Этап 5 (докачка через slskd).
6. Сформировать файлы `MusicRaw/playlists_m3u/<Название>.m3u`.
7. После докачки (Этап 5) — обновить `.m3u` с учётом новых файлов.

**Результат этапа:** плейлисты 1:1 с оригиналами (там, где трек есть в коллекции),
единый список недостающих треков для докачки.

### Этап 5 — Заполнение пробелов (недостающие треки)

**Цель:** автоматически докачать все треки, которые есть в VK-плейлистах/Shazam/Яндекс.
Музыке, но отсутствуют в кеше. Процесс автоматизирован через slskd (Soulseek) —

**Важно:** yt-dlp исключён (корпоративный запрет).

Шаги:

1. Собрать единый список недостающих треков (из этапа 4 + список Shazam + список
   Яндекс.Музыка, сверенный с библиотекой через fuzzy-matching).

2. Развернуть **slskd** (Soulseek-клиент) на VPS в docker-compose:
   ```yaml
   slskd:
     image: slskd/slskd:latest
     restart: unless-stopped
     ports:
       - "5030:5030"    # Web UI
       - "5031:5031"    # API
     volumes:
       - ./slskd-data:/app
       - ./music-inbox:/downloads
     environment:
       SLSKD_HTTP_PORT: 5030
       SLSKD_HTTPS_PORT: 5031
   ```
   **Важно:** привязать slskd к VPN-интерфейсу (WireGuard-контейнер рядом) —
   Soulseek-трафик должен идти через VPN.

3. Для каждого трека из списка — агент с Mac дёргает slskd API:
   - Поиск по `Артист Название`
   - Фильтр по качеству (предпочитать 320kbps / FLAC)
   - Скачивание → файл падает в `/music-inbox/` на VPS
   - Приоритет: сначала треки из VK-плейлистов (важнее всего), затем Shazam,
     затем Яндекс.Музыка

4. Все докачанные треки прогнать через **тот же скрипт парсинга имён + beets-импорт**, что
   использовался на Этапе 3 для кеша Kate Mobile. Файлы из slskd приходят с читаемыми
   именами (Soulseek-клиенты обычно сохраняют в формате `Артист - Название`), так что
   парсинг сработает ещё надёжнее. Результат — единый формат и структура для всей коллекции.

5. После импорта — перегенерировать/дополнить `.m3u` плейлисты VK (повторить Этап 4
   для обновлённой библиотеки), чтобы подхватить новые треки.

**Результат этапа:** максимально полная коллекция — все треки из всех источников
собраны в библиотеке и привязаны к плейлистам. Оставшиеся пробелы — только то, что
технически невозможно найти. Качество докачанного — 320kbps MP3 / FLAC (лучше кеша VK).

### Этап 6 — Перенос на сервер и бэкап

**Цель:** финальная библиотека закачана на VPS, настроен бэкап в Mail.ru облако.

**Важно:** rclone не работает с Mail.ru (проверено). Используем WebDAV.

Шаги:

1. Перенести `~/Music/Library/` с Mac на VPS в `/music` (через `rsync -avz` по SSH).

### Этап 8 — Автоматизация добавления новой музыки (с любого устройства)

**Цель:** добавление новых треков возможно с любого устройства (Mac, телефон),
без привязки к конкретному компьютеру.

**Важное ограничение:** Navidrome НЕ поддерживает загрузку файлов через свои клиенты
или API — он только читает готовую папку `/music` на диске.

**Решение — Syncthing (ноутбук ↔ VPS) + SFTP (телефон):**

1. Установить **Syncthing** на VPS + основной ноутбук:
   - На VPS создаётся папка-инбокс `/music-inbox/`.
   - Syncthing синхронизирует её с папкой `~/MusicInbox` на ноутбуке.
   - **Телефон:** Syncthing-Fork на Android проблематичен (смена мейнтейнера Google Play).
     Для редкой загрузки с телефона — **SFTP** через Material Files (бесплатный
     файловый менеджер с поддержкой SFTP). Закинул файл напрямую в `/music-inbox/` на VPS.

2. Как это работает:
   - **С ноутбука:** бросил MP3-файл в `~/MusicInbox` → Syncthing доставил на VPS.
   - **С телефона:** открыл Material Files → SFTP к VPS → закинул в `/music-inbox/`.

3. Настроить watcher-скрипт на VPS (`scripts/watch-inbox.sh`):
   - Следит за `/music-inbox/` на новые файлы (через `inotifywait`).
   - При появлении — прогоняет скрипт парсинга имён + beets import:
     ```bash
     beet import -q /music-inbox/
     ```
   - beets переносит обработанные файлы в `/music/`, удаляя исходники из инбокса.
   - Триггерит пересканирование Navidrome:
     ```bash
     curl -X POST http://localhost:4533/rest/startScan
     ```
   - **Важно:** защита от гонки — `flock` на lock-файл, чтобы параллельный запуск
     не сломал импорт.

**Результат этапа:** добавление новой музыки с ноутбука = «бросил файл в папку MusicInbox
→ через минуту трек в Navidrome с правильными тегами и обложкой». С телефона — открыл
Material Files → SFTP → закинул файл. Без браузеров, без кнопок.

### Этап 9 — Аудиокниги (опционально, Audiobookshelf)

**Статус:** отложенный этап. Делается когда возникнет потребность в аудиокнигах.

**Цель:** отдельный self-hosted сервис для аудиокниг с запоминанием позиции, закладками,
регулировкой скорости и удобным Android-клиентом.

**Почему не Navidrome:** Navidrome заточен под музыку (shuffle, 3-5 минутные треки).
Аудиокнигам нужно другое: позиция и закладки на сервере, скорость 1.2-1.5x,
sleep timer, отсутствие пересечения с музыкой в shuffle.

**Решение — Audiobookshelf:**
- Отдельный Docker-контейнер на том же VPS, не конфликтует с Navidrome.
- Хранит позицию, закладки, прогресс на сервере — не теряется при смене устройства.
- Бесплатный Android-клиент с отличным интерфейсом.
- Автоматически определяет метаданные (автор, серия, narrator).
- Подкасты тоже поддерживает, если понадобятся.

Шаги:
1. Добавить Audiobookshelf в docker-compose рядом с Navidrome:
   ```yaml
   audiobookshelf:
     image: ghcr.io/advplyr/audiobookshelf:latest
     restart: unless-stopped
     ports:
       - "13378:80"
     volumes:
       - ./audiobooks:/audiobooks
       - ./abs-config:/config
       - ./abs-metadata:/metadata
   ```
2. Настроить доступ в Caddy — Audiobookshelf будет доступен на поддомене того же домена.
3. Подготовить папку для аудиокниг:
   - Структура: `Автор/Серия/Книга/файлы.mp3` или `Автор/Книга/файлы.mp3`.
   - Audiobookshelf сам подхватит и сматчит метаданные.
4. Загрузка аудиокниг:
   - **С ноутбука:** через Syncthing (та же папка-инбокс или отдельная).
   - **С телефона:** через SFTP (Material Files).
   - beets не нужен — Audiobookshelf сам сканирует папку и определяет метаданные.
5. Установить **Audiobookshelf Android-клиент** (бесплатный, из Google Play) →
   подключить к серверу.
6. Настроить бэкап папки `/audiobooks` и конфига в Mail.ru облако (добавить в
   cron-скрипт из Этапа 6).

**Результат этапа:** аудиокниги живут в отдельном сервисе, не пересекаются с музыкой,
позиция синхронизируется между устройствами, прогресс не теряется.

## Как продолжить с середины (для новой сессии)

1. Прочитать «Сводка» и «Контекст и решения» выше — это даёт полное понимание решённых
   вопросов, чтобы не переспрашивать то, что уже зафиксировано.
2. Проверить, какие шаги внутри нужного этапа уже выполнены (отмечать выполненные шаги
   вручную `[x]` по мере прохождения — сейчас чек-боксов нет, добавляются по факту работы).
3. Если развилка (клиент, способ бэкапа) ещё не выбрана к моменту этапа — решить её по
   таблице в разделе «Открытые развилки» перед тем, как приступать к шагам.
4. Начинать работу с явного указания этапа, например: «продолжи с этапа 3» —
   агент должен прочитать весь файл для контекста, затем выполнять только шаги нужного
   этапа.

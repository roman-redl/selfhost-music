## Сводка

**Проблема:** VK отключил публичное API, Kate Mobile больше не может докачивать новую музыку.
Доступен только локальный кеш (MP3-файлы с названиями вида `Артист_Название_цифры.mp3`).
Нужно решение на годы вперёд, без привязки к VK.

**Решение:**
1. Развернуть **Navidrome** (self-hosted музыкальный сервер, Subsonic API) на **Oracle Cloud
   Free Tier** (ARM VPS, нужен апгрейд до PAYG для защиты от удаления через 60 дней).
2. Взять исходники музыки: кеш Kate Mobile (полностью выгружен в Mail.ru облако — единый
   источник аудиофайлов) + Shazam-история + Яндекс Музыка (небольшая часть) + VK-плейлисты
   для восстановления структуры и поиска недостающего.
3. Нормализовать **кеш Kate Mobile** (единственный источник аудиофайлов): **распарсить имена
   файлов** (формат `Артист_Название_цифры` → ID3-теги), затем через **beets** (структура
   папок, обложки альбомов). Shazam и Яндекс.Музыка — только списки, без файлов; их
   нормализация произойдёт на Этапе 5 после докачки.
4. Восстановить плейлисты VK 1:1 (копипаст страниц VK → fuzzy-матчинг с коллекцией) →
   `.m3u` файлы, которые подхватит Navidrome.
5. **Автоматически докачать** недостающие треки через **slskd** (Soulseek-клиент на Mac) —
   одноразовая операция на Этапе 5. После этого загрузка новой музыки — через Syncthing/SFTP,
   Soulseek больше не нужен. **yt-dlp исключён** (корпоративный запрет).
6. Настроить клиенты на всех устройствах (Mac, Windows, Android) с офлайн-кешем и, по
   возможности, единым интерфейсом.
7. Настроить бэкап музыки/базы Navidrome в облако Mail.ru через **WebDAV** (rclone не
   работает с Mail.ru — проверено). Бэкап данных **и** базы Navidrome — отдельно.
8. Сделать добавление новой музыки возможным с любого устройства: **Syncthing** между
   ноутбуком и VPS для основного сценария, **SFTP** с телефона для редких случаев.

**Инструмент выполнения:** Claude Code на Mac — вся ручная работа (серверная настройка,
скрипты нормализации, парсинг метаданных) делается через агента, пользователь только
принимает решения на развилках.

**Статус:** ✅ План закрыт. Этапы 1–8 завершены, сервер работает, музыка доступна, клиенты настроены, автоимпорт + автообложки работают. Осталось на будущее: бэкап Mail.ru (не настроен) и Этап 9 (аудиокниги) — см. раздел «Осталось на будущее» в конце. Правила и инциденты вынесены в [project-context.md](project-context.md), операционный минимум — [CLAUDE.md](../CLAUDE.md).

**Репозиторий:** [roman-redl/selfhost-music](https://github.com/roman-redl/selfhost-music) — конфиги, скрипты, docker-compose, документация.

### Компоненты

| Компонент | Роль | Коротко |
|---|---|---|
| **Oracle Cloud VPS (PAYG)** | Хостинг | Бесплатный сервер 4 CPU / 24 GB RAM. PAYG-апгрейд защищает от автоматического удаления через 60 дней |
| **Navidrome** | Музыкальный сервер | Self-hosted аналог Spotify/Apple Music. Раздаёт музыку по Subsonic API, лёгкий (Go), только музыка |
| **Caddy** | HTTPS-прокси | Автоматический SSL (Let's Encrypt), проксирует запросы к Navidrome. Без него сервер недоступен из интернета |
| **beets** | Нормализация | Организует музыку: правильные теги, структура папок `Артист/Альбом/`, обложки. Не для распознавания (имена уже есть), а для порядка |
| **Скрипт парсинга имён** | Извлечение тегов | Берёт имя файла `Артист_Название_цифры.mp3` и записывает ID3-теги в MP3. Свой скрипт, не beets |
| **slskd** | Докачка недостающего (разово) | Soulseek-клиент, запускается на Mac **только на Этапе 5**. Агент ищет треки через API, качает локально. После докачки не нужен — новая музыка добавляется через Syncthing/SFTP |
| **Syncthing** | Доставка файлов на VPS | P2P-синхронизация папки `MusicInbox` между ноутбуком (Mac/Win) и VPS. Бросил файл в папку → через минуту в Navidrome |
| **SFTP (Material Files)** | Загрузка с телефона | Для редких случаев. Material Files — бесплатный файловый менеджер на Android с поддержкой SFTP. Закинул напрямую в `/music-inbox/` |
| **watcher + inotify** | Автообработка | Следит за `/music-inbox/`, при появлении новых файлов запускает beets и триггерит пересканирование Navidrome |
| **WebDAV (davfs2)** | Бэкап в облако | Монтирует Mail.ru облако как папку на VPS. Cron раз в день синхронизирует `/music/` и `/data/`. rclone не работает с Mail.ru |
| **Supersonic** | Десктоп-клиент | Бесплатный, Mac + Windows, полный офлайн-кеш (выбрал плейлист → слушаешь без интернета) |
| **Substreamer** | Android-клиент | Бесплатный, современный UI, полный офлайн-кеш, синхронизация плейлистов |
| **Audiobookshelf** | Аудиокниги (будущее) | Отдельный сервис для аудиокниг: позиция, скорость, sleep timer. Не смешивается с музыкой |

## Подробный план

### Этап 1 — Инфраструктура (сервер)

**Цель:** поднять рабочий Navidrome на Oracle Cloud Free Tier, доступный со всех устройств.

**Статус:** ✅ завершён (2026-08-06).

**Конфигурация сервера:**
- Oracle Cloud, Frankfurt, PAYG
- Ampere A1, 4 OCPU, 24 GB RAM, 200 GB диск
- Ubuntu 24.04 aarch64, Docker 29.7.2
- Домен: DuckDNS (`redl-music.duckdns.org`) + Caddy + Let's Encrypt
- SSH-ключ: `~/.ssh/id_ed25519_oracle`

**Пути на VPS:**
| Путь | Назначение |
|------|-----------|
| `/opt/selfhost-music/` | Корень репозитория |
| `/opt/selfhost-music/music/` | Музыка (readonly для Navidrome) |
| `/opt/selfhost-music/music-inbox/` | Входящие файлы для обработки |
| `/opt/selfhost-music/data/` | База Navidrome |
| `/opt/duckdns/duck.sh` | Cron для обновления DuckDNS |

**Отклонения от исходного плана:**
- `rate_limit` в Caddyfile убран — не работает без плагина в бесплатной версии
- Порты 80/443 открывались вручную в Security List подсети Oracle
- Интерфейс Oracle изменился — нет вкладки Resources, инстанс создаётся через Compute → Instances
- Navidrome-пользователь создан, доступ проверен

Шаги (как было сделано):
1. Зарегистрировать Oracle Cloud Free Tier аккаунт (нужна карта, пользователь делает сам).
2. **Сразу апгрейднуть до PAYG** (Billing → Upgrade). Без этого Oracle удалит ВМ через 60
   дней (политика октября 2025). В пределах Free Tier лимитов плата $0.
3. Создать ARM-инстанс (Ampere A1, 4 OCPU / 24GB RAM). **Важно:** почти наверняка будет
   ошибка `Out of host capacity`. Запустить retry-скрипт
   ([oci-always-free](https://github.com/dan-hollis/oci-always-free)) и ждать — может занять
   от нескольких часов до нескольких дней. Скрипт пробует каждые 60 секунд.
4. Настроить базовую безопасность: SSH-ключ, отключить пароль, ufw на порты 22 (SSH),
   443 (HTTPS), закрыть остальное.
5. Установить Docker + Docker Compose.
6. Развернуть Navidrome через docker-compose:
   ```yaml
   version: '3'
   services:
     navidrome:
       image: deluan/navidrome:latest
       restart: unless-stopped
       ports:
         - "4533:4533"
       volumes:
         - ./data:/data
         - ./music:/music:ro
       environment:
         ND_MUSICFOLDER: /music
         ND_DATAFOLDER: /data
         ND_SCANSCHEDULE: "1h"
         ND_ENABLETRANSCODING: "true"
         ND_LOGLEVEL: info
   ```
7. Настроить HTTPS и доступ извне:
   - Tailscale не подходит — на корпоративном Mac нельзя включать сторонние VPN.
   - **Caddy** как reverse proxy с автоматическим Let's Encrypt.
   - Нужен домен. Бесплатный вариант — DuckDNS (`*.duckdns.org`). Более надёжный —
     свой домен за ~200-300₽/год.
   - Caddy автоматически получает SSL-сертификат, настраивает HTTPS, проксирует
     запросы на Navidrome (порт 4533).
   - Добавить rate-limiting в Caddy для защиты от брутфорса:
     ```
     handle {
         rate_limit {remote_host} 10r/s
         reverse_proxy navidrome:4533
     }
     ```
   - Итог: `https://music.<твой-домен>.duckdns.org` доступен из любого браузера.
8. Проверить доступ к веб-интерфейсу Navidrome с Mac.
9. Создать пользователя/пароль в Navidrome для дальнейшего использования в клиентах.

**Результат этапа:** Navidrome работает на VPS, доступен с Mac по домену, готов принимать
музыку в `/music`. VPS защищён от удаления (PAYG).

### Этап 2 — Сбор исходников музыки

**Цель:** собрать все источники в `MusicRaw/` (в корне репозитория) перед обработкой.

**Статус:** ✅ завершён (2026-08-06).

#### Структура MusicRaw/

```
MusicRaw/
├── kate_mobile/              ← 1029 MP3, 8.7 GB
├── playlists/                ← 41 VK-плейлист (909 треков, полные списки)
├── новая музыка.txt          ← 10 треков (из VK «Моя музыка», нет в кеше)
├── yandex/
│   └── яндекс музыка.txt     ← 31 трек (полный «My Favorites»)
└── youtube/
    └── ютуб топ.txt          ← 36 треков (фильтровано)
```

#### Источники и порядок действий

1. **Кеш Kate Mobile** (единственный источник аудиофайлов):
   - Скачан из облака Mail.ru (`hljkhd@mail.ru`, папка `Other/audio_cache`) через
     локально примонтированный диск Mail.ru Disk-O.
   - 1029 MP3-файлов, 8.7 GB. Формат имён: `Артист_Название_цифры_цифры.mp3`.
   - Даты файлов: с 31 июля 2023 по 28 апреля 2026. Основная масса — 2023 (791 файл).
   - Последний сеанс загрузки Kate Mobile: 28 апреля 2026 (80 файлов одной датой).
   - Всё, что добавлено в VK после 28 апреля 2026, в кеше отсутствует.

2. **VK-плейлисты** (восстановление структуры):
   - 41 плейлист скопипащен из десктоп-версии VK. Каждый плейлист сохранён как
     отдельный `.txt` в `MusicRaw/playlists/`.
   - Формат: построчно `Артист — Название`. Плейлисты **полные** — содержат все треки,
     включая те, что уже есть в кеше.
   - На Этапе 4 будет fuzzy-матчинг с кешем, ненайденное — в докачку (Этап 5).

3. **VK «Моя музыка»** (новая музыка вне плейлистов):
   - Страница «Моя музыка» сохранена как PDF (5 страниц, ~105 треков).
   - Текст извлечён через pdftotext/Tesseract OCR и сверен с кешем.
   - Треки, отсутствующие в кеше (10 шт.) — в `MusicRaw/новая музыка.txt`.
   - Это треки, добавленные в VK после последней синхронизации Kate Mobile, не попавшие
     ни в один плейлист.

4. **Яндекс.Музыка** (отдельная коллекция):
   - Экспортирован полный плейлист «My Favorites» (31 трек) → `yandex/яндекс музыка.txt`.
   - Преимущественно synthwave/электроника, отсутствующая в VK-кеше (26 из 31 новых).
   - **Правило:** полный список, без фильтрации. На Этапе 5 — докачка недостающего.

5. **Shazam** (история распознаваний):
   - Экспортирован через официальный экспорт Shazam (файл `SyncedSongs.csv`, 501 запись).
   - Дедублицировано до 356 уникальных треков.
   - **Правило фильтрации:** из Shazam исключены треки, уже присутствующие в любом из:
     кеша Kate Mobile, VK-плейлистов, Яндекс.Музыки, «Моя музыка».
   - Оставлено 262 трека → `shazam/shazam.txt`.
   - **Логика:** лучше сохранить лишнее и дать пользователю удалить ненужное при
     прослушивании, чем потерять трек, который был распознан, но не добавлен в VK
     (пользователь не системно переносил Shazam → VK).

6. **YouTube «Топ песенки»** (плейлист избранного):
   - 143 видео в плейлисте, скопипащено из десктоп-версии YouTube.
   - Извлечено 123 названий треков, отфильтровано против всех остальных источников.
   - Оставлено 36 треков → `youtube/ютуб топ.txt`.
   - **Правило:** всё, чего нет ни в одном другом источнике (кеш, VK-плейлисты,
     Яндекс, Shazam, «Моя музыка»).

#### Правила пересечения источников

| Источник | Тип данных | Фильтрация |
|----------|-----------|------------|
| Kate Mobile | Аудиофайлы (MP3) | SSOT, не фильтруется |
| VK-плейлисты | Списки треков | Полные списки |
| VK «Моя музыка» | Список треков | Только отсутствующее в кеше |
| Яндекс.Музыка | Список треков | Полный список |
| Shazam | Список треков | Всё, чего нет в кеше/плейлистах/яндексе/VK |
| YouTube | Список треков | Всё, чего нет в кеше/плейлистах/яндексе/VK/Shazam |

**Результат этапа:** все исходники собраны в `MusicRaw/`. Кеш — единственный источник
аудио. Списки треков готовы для сверки (Этап 4) и докачки (Этап 5).

### Этап 3 — Парсинг имён файлов и нормализация (beets)

**Цель:** превратить сырой кеш в единую библиотеку `Артист - Название` с правильными
тегами и структурой папок, готовую к раздаче через Navidrome.

**Статус:** ✅ завершён (2026-08-07).

**Стратегия:** 95% файлов уже содержат артиста и название в имени
(`Yello_Oh Yeah_494949805_456240039.mp3`). Поэтому НЕ используем AcousticID/Chromaprint —
вместо этого парсим имена файлов → пишем ID3-теги → beets только для организации.

#### Выполненные шаги

1. **Установлены инструменты:**
   ```bash
   brew install beets         # beets 2.13.1
   pip3 install mutagen       # mutagen 1.48.1
   ```

2. **Скрипт `scripts/parse_filenames.py`:**
   - Парсит имена `Артист_Название_<owner_id>_<track_id>.mp3`
   - Отрезает два последних числовых сегмента (owner_id + track_id)
   - Разделитель артист/название — первый `_` в оставшейся части
   - Пишет ID3-теги (artist, title) через mutagen
   - Результат: 1026/1030 распарсено автоматически, 4 вручную
   - 4 ручных: 3 файла с отрицательными ID, 1 со сложным именем

3. **Настроен beets** (`~/.config/beets/config.yaml`):
   ```yaml
   directory: MusicRaw/Library/          # в репозитории!
   library: MusicRaw/beets-library.db
   import:
     copy: no      # файлы уже в репо
     move: no
     write: yes
   paths:
     singleton: Singletons/$artist - $title
   plugins: fetchart embedart fromfilename
   ```

4. **Импорт в beets:**
   - Команда: `beet import -A -q -s MusicRaw/kate_mobile/`
   - Флаги: `-A` (без автопривязки к MusicBrainz), `-q` (без интерактива),
     `-s` (синглтон-режим — каждый трек отдельно)
   - Результат: 997 треков импортированы, затем 13 дополнительных версий
     добавлены вручную (дубликаты с разным размером + 9 неизвестных треков).
     Итого 1010 треков в Library.
   - 642 уникальных артиста

5. **Отклонения от плана:**
   - Библиотека размещена в `MusicRaw/Library/` (в репозитории), а не в `~/Music/Library/`

#### Стратегия: матчинг ТОЛЬКО агентами (fuzzy-скрипты запрещены)

**Проблема:** чисто алгоритмический fuzzy-матчинг (rapidfuzz, difflib) принципиально не
понимает семантику:
- Не отличает «Radio Edit» от оригинала (разные строки, но одна песня)
- Не видит, что «Токийский гуль — 1 опенинг» = `Tokyo Ghoul - Unravel.mp3` (перевод + доменные знания)
- Даёт ложные срабатывания на совпадении имени артиста при разных названиях песен
- Бесполезен при Cyrillic/Latin-транслитерации имён (Игорь Корнелюк ≠ Igor Kornelyuk для fuzzy)

**Решение — ТОЛЬКО агенты, без промежуточного скрипта:**
- Матчинг всегда делается агентами Claude Code в параллельном режиме
- Агенты видят то, чего не видит алгоритм: семантику, контекст, переводы, жанровые знания
- Типичный размер: 10 агентов параллельно, каждый обрабатывает ~30 треков
- Никаких скриптов-посредников — только прямые решения агентов

**Почему скрипты вредны:**
- Создают ложное чувство прогресса (70% матчей, но 2-3% из них ложные)
- Требуют второго прохода агентами для исправления ошибок — двойная работа
- Ложные матчи сложнее найти, чем пропущенные (агент должен перепроверить ВСЕ матчи, а не только uncertain)

### Этап 8 — Автоматизация добавления новой музыки

**Статус:** ✅ завершён (2026-08-10).

#### Как работает добавление

```
Mac: ~/MusicInbox/          VPS: /opt/selfhost-music/
├── новый_трек.mp3 ──Syncthing──→ music-inbox/новый_трек.mp3
                                     │
                            watcher (inotifywait) замечает
                                     │
                            mv → music/новый_трек.mp3
                                     │
                            get_cover.py → Deezer/iTunes API
                                     │
                            обложка встроена в MP3
                                     │
                            Navidrome watcher замечает
                                     │
                            Трек в библиотеке с обложкой ✅
```

#### Компоненты

| Компонент | Статус | Описание |
|-----------|--------|----------|
| **Syncthing** Mac ↔ VPS | ✅ | Папка `~/MusicInbox` синхронизируется с `/opt/selfhost-music/music-inbox/` |
| **Watcher** (systemd) | ✅ | `music-watcher.service`, скрипт `scripts/watch-inbox.sh` |
| **Автообложка** | ✅ | `scripts/get_cover.py` — Deezer API + iTunes API, при появлении нового MP3 |
| **SFTP с телефона** | 🔜 | Material Files → SFTP к VPS, закинуть в `music-inbox/` |

#### Обложки для новых треков

**Автоматизировано.** При добавлении трека через `~/MusicInbox`:
1. Файл перемещается в `/music/`
2. `get_cover.py` ищет обложку через Deezer API → iTunes API
3. Найденная обложка встраивается в MP3 (ID3 APIC)
4. Navidrome подхватывает при следующем сканировании

Если обложка не найдена или не нравится — заменить вручную (см. `docs/howto-add-music-and-covers.md`).

### Этап 9 — Аудиокниги (опционально, Audiobookshelf)

**Статус:** отложенный этап. Делается когда возникнет потребность в аудиокнигах.

**Цель:** отдельный self-hosted сервис для аудиокниг с запоминанием позиции, закладками,
регулировкой скорости и удобным Android-клиентом.

**Почему не Navidrome:** Navidrome заточен под музыку (shuffle, 3-5 минутные треки).
Аудиокнигам нужно другое: позиция и закладки на сервере, скорость 1.2-1.5x,
sleep timer, отсутствие пересечения с музыкой в shuffle.

**Решение — Audiobookshelf:**
- Отдельный Docker-контейнер на том же VPS, не конфликтует с Navidrome.
- Хранит позицию, закладки, прогресс на сервере — не теряется при смене устройства.
- Бесплатный Android-клиент с отличным интерфейсом.
- Автоматически определяет метаданные (автор, серия, narrator).
- Подкасты тоже поддерживает, если понадобятся.

Шаги:
1. Добавить Audiobookshelf в docker-compose рядом с Navidrome:
   ```yaml
   audiobookshelf:
     image: ghcr.io/advplyr/audiobookshelf:latest
     restart: unless-stopped
     ports:
       - "13378:80"
     volumes:
       - ./audiobooks:/audiobooks
       - ./abs-config:/config
       - ./abs-metadata:/metadata
   ```
2. Настроить доступ в Caddy — Audiobookshelf будет доступен на поддомене того же домена.
3. Подготовить папку для аудиокниг:
   - Структура: `Автор/Серия/Книга/файлы.mp3` или `Автор/Книга/файлы.mp3`.
   - Audiobookshelf сам подхватит и сматчит метаданные.
4. Загрузка аудиокниг:
   - **С ноутбука:** через Syncthing (та же папка-инбокс или отдельная).
   - **С телефона:** через SFTP (Material Files).
   - beets не нужен — Audiobookshelf сам сканирует папку и определяет метаданные.
5. Установить **Audiobookshelf Android-клиент** (бесплатный, из Google Play) →
   подключить к серверу.
6. Настроить бэкап папки `/audiobooks` и конфига в Mail.ru облако (добавить в
   cron-скрипт из Этапа 6).

**Результат этапа:** аудиокниги живут в отдельном сервисе, не пересекаются с музыкой,
позиция синхронизируется между устройствами, прогресс не теряется.
